Usage notes

TopicFlag / syntaxNotes
Command syntaxvol -f <image> <plugin> [options]Volatility 3 plugin names are namespaced and case-sensitive. The entry point is `vol` (or `python3 vol.py`). Use `vol -h` for global options and `vol <plugin> -h` for plugin-specific ones.
Listing pluginsvol -hThe full plugin list for your installed version is printed at the bottom of `vol -h`. Plugin sets differ between versions — always check against your own install rather than a cheat sheet.
Deprecated namespaceswindows.malware.* / linux.malware.*As of Volatility 3 v2.2x, malware-detection plugins moved into `.malware` subpackages. The old top-level names (windows.malfind, linux.check_syscall, ...) still work but print a deprecation warning. This sheet uses the new names.
Windows symbolsAutomaticWindows symbol tables are downloaded automatically from the Microsoft symbol server on first use. A failure here almost always means no network access or an unsupported build.
Linux symbolsdwarf2jsonLinux requires an ISF file built from the exact kernel's debug symbols (`dwarf2json linux --elf vmlinux > kernel.json`), placed in `volatility3/symbols/linux/`. No matching ISF means every Linux plugin fails.
Output formats-r pretty | csv | json`-r csv` is the fastest way to get plugin output into a spreadsheet or grep pipeline; `-r json` for scripting. Add `-q` to suppress progress output.
Dumping to disk-o <dir> --dumpThe output directory flag `-o` is global and comes before the plugin name. Plugins that write files (dumpfiles, pedump, memmap, elfs, module_extract) need it.
Scoping to a process--pid <PID>Most process plugins accept `--pid`. Scope early: running dlllist or handles across every process on a busy image is slow and noisy.
PerformanceScan vs list`*scan` plugins brute-force the physical layer and are slow but see hidden objects; list-walking plugins are fast but trust kernel structures a rootkit may have edited. Run both and diff them.
Not covered heremac.* pluginsVolatility 3 also ships a macOS plugin set (mac.pslist, mac.netstat, mac.malfind, ...). It is out of scope for this workbook and rarely used in CTF challenges.
Optional dependenciesyara-python, pycryptodome, capstoneSome plugins are hidden if a dependency is missing: yarascan/vadyarascan/vmayarascan/mftscan need yara-python, the hashdump/lsadump/cachedump family needs pycryptodome, and the direct/indirect syscall plugins need capstone. If a plugin here is 'not found', install the dependency before assuming your version lacks it.
Name resolutionShorthand vs full nameThe CLI accepts a shortened plugin name (windows.pslist) as long as it is unambiguous. Ambiguous prefixes are rejected: use windows.windows.Windows, since windows.windows also prefixes windows.windowstations.
YARA flags--yara-string / --yara-fileRules are passed with --yara-string (inline), --yara-file (a .yar file), or --yara-compiled-file. Add --wide for UTF-16 strings and --insensitive for case-insensitive matching.
volshellpython3 volshell.py -f <image>Interactive structure exploration. -w / -l / -m select Windows, Linux or Mac mode; --pid sets process context. Inside: hh() for help, ps() to list processes, cc(pid=N) to change context, dt() to display a structure type, db()/dd() to dump bytes. The fastest way to learn what a plugin is actually doing.
Reading Vol 2 writeupsSee the translation sheetAlmost every public walkthrough uses Volatility 2 syntax with --profile=. The 'Volatility 2 to 3 Translation' sheet in this workbook maps the old commands, and flags the ones with no Volatility 3 equivalent.
Version notev2.28 (stable)Plugin names and descriptions in this workbook were verified against the Volatility 3 stable branch, version 2.28. Older installs will lack some plugins listed here.
