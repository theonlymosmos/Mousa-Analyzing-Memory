Triage indicators & gotchas

Reading the output is the hard half. What each result means, and where it will mislead you.

AreaWhat to look forWhy it matters / pitfall
Process listingProcesses with 0 threads, 0 handles, or a populated Exit timeThey are terminated but still linked in the active list. Not a rootkit finding — a common false lead for beginners.
Process listingSystem (PID 4) and smss.exe with no Session IDExpected, not an anomaly: System starts before sessions exist and smss.exe is the session manager itself.
Process listingProcesses present in psscan but absent from pslistEither terminated, or unlinked from the EPROCESS list by DKOM. Check the Exit time before calling it a rootkit.
Process listingProcesses in pslist but not psscanUsually pool memory reuse or a scanning miss — the list view is generally the more reliable of the two for live processes.
Process lineagesvchost.exe whose parent is not services.exe, or with no -k argument in its command lineThe single highest-yield Windows anomaly. Legitimate svchost is always services-spawned and always has a -k service group.
Process lineagecsrss.exe and wininit.exe showing a PPID that no longer existsNormal: their parent smss.exe exits after boot. Orphaned PPID alone is not suspicious for these.
Process lineageOffice, browser, or Acrobat processes with a shell or script host childWINWORD.EXE spawning powershell.exe, cmd.exe or wscript.exe is the classic initial-access pattern.
Image pathsA system binary name running from anywhere other than System32 or SysWOW64Masquerading is cheap and common. Always compare the path, not just the process name.
VAD protectionsPAGE_NOACCESS in vadinfo outputvadinfo reports the ORIGINAL protection from the first allocation, not the current one. A region shown as NOACCESS may still be executable now.
malfindRWX private VADs containing an MZ headerAn injected PE. Regions with no MZ but valid-looking instructions are shellcode — disassemble before concluding.
malfindDozens of RWX hits in browsers, .NET, or Java processesJIT compilers allocate RWX legitimately. malfind is a lead generator, not a verdict; correlate with thread start addresses and module backing.
DLL listingA Wow64 process showing very few DLLsThe PEB lists are truncated for Wow64. Use windows.malware.ldrmodules instead of dlllist for 32-bit processes on 64-bit systems.
ThreadsThread start addresses that map to no loaded moduleStronger evidence than malfind alone: code executing from unbacked memory. windows.malware.suspicious_threads automates this check.
NetworkEndpoints whose owning PID does not appear in any process listingEither a hidden process or a stale pool artifact. netscan is a scanner, so corrupt and historical entries are expected.
Networknetscan returning nothing on a busy systemTry --include-corrupt to relax validation, and cross-check with windows.netstat, which walks live structures instead.
Command historycmdscan showing fewer commands than expectedThe default MaxHistory is 50 and is user-configurable via HKCU\Console\HistoryBufferSize. Use --max-history and prefer consoles, which returns output as well as input.
HandlesUnusual named mutexesMalware families use hardcoded mutex names as single-instance markers — one of the best pivots from a memory image to threat-intel attribution.
Scanning generallyAny *scan plugin resultScanners find objects in pool memory that may be freed, reused, or partially overwritten. A hit proves the object existed at some point, not that it was live at capture time.
ExtractionDumping fails with a paged-out headerIf the page holding the PE header is not resident, pedump and dlllist --dump fail. Fall back to vadinfo --dump and rebuild the header manually.
TimestampsAll plugin timestampsVolatility reports UTC. Reconcile against the system time zone before building a timeline or correlating with logs.
AcquisitionStructures that contradict each otherA dump taken over minutes on a live system is not an atomic snapshot. Smear produces genuinely inconsistent structures — do not force a rootkit narrative onto it.
Linux symbolsPlugins returning empty tables rather than errorsA near-match ISF file is worse than none: offsets resolve to garbage and output looks plausible but is wrong. Confirm the banner matches your symbol file exactly.
Linux processesBracketed names in pslist outputThose are kernel threads. Use --decorate-comm to distinguish kernel threads and user threads before treating one as anomalous.
Linux moduleslsmod output that looks cleanClean lsmod means nothing on its own — it is the list a rootkit unlinks from. Run linux.malware.modxview to compare it against carved and sysfs views in one table.
